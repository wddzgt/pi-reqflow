# 默认约束与项目配置

本文件描述流程门禁和运行配置。代码质量、语言预设及使用方团队规则另见 [项目代码规范约束](coding-standards.md)；`policy-preview` 展示规范配置，但不执行代码扫描。

方案、代码实施和前后端/QA 评审可分别配置模型，见 [Agent 模型配置](agent-models.md)。`policy-preview` 显示每个 Agent 的最终 provider/model 和配置来源；模型修改纳入项目配置哈希。

## 规则分层

系统默认门禁来自核心状态机，项目配置不能关闭：产品确认版本化契约；相关研发和 QA 对同一版本评审；具名研发审核方案后才能改代码；实施后的真实变更和验证结果由具名研发审核人确认后才能测试部署；测试环境人工验收；生产发布另需发布角色审批；所有状态与证据进入需求审计。Pi 不自行提交、推送、合并或删除 Git 分支。实施前保留文件快照，回退遇到后续修改会拒绝覆盖。

这些门禁对应真实研发中的需求评审、设计审核、代码审核、回归验证、测试验收和发布批准。对已有接口、数据或历史功能的影响，不能由模型自行声明“无风险”来跳过人工责任。快速路径仅减少角色评审和方案生成阶段的手动操作，仍停在方案审核、实际变更审核与测试验收。

项目必须显式填写执行器、模型、可改路径、环境变量名称、检查命令、资源上限、测试部署和生产发布方式。系统不根据仓库内容猜测检查命令、密钥、发布环境或分支。`fastPath` 未配置时关闭；模板显式关闭生产发布。运行检查的 Docker 沙箱是可选配置，未设置时会在策略预览中明确提示宿主机执行边界。

| 由项目配置 | 建议的初始选择 | 配置时需核对 |
| --- | --- | --- |
| 可改路径与排除路径 | 只列实际源码与测试目录；排除环境文件、构建产物 | 能否触及接口、数据库迁移、生产配置及敏感文件 |
| 检查命令 | 至少覆盖需求相关自动测试与原有关键路径 | 命令必须真实验证行为，版本输出或单纯构建不能充当回归测试 |
| 检查运行环境 | 可信仓库可用受控主机；不可信检查配置固定摘要的 Docker 镜像 | 镜像、依赖、文件权限、网络与 Docker 守护进程 |
| 资源与成本 | 按团队模型价格和项目规模设置上限 | 自定义模型的价格元数据是否准确 |
| 快速路径 | 默认关闭；先在真实历史需求样本上试运行 | 文件与验收项数量、可改路径与受影响文件大小；不强制改测试文件 |
| Git 分支与部署 | 需求独立分支；测试部署先用受控环境；生产发布先关闭 | 远端分支、Jenkins 作业和发布责任人的实际流程 |

## 配置交互

CLI 是核心入口，网页只需调用同一策略说明函数作为可选适配器。初始化前运行 `policy-preview`，得到内置门禁、项目规则、宿主机执行提示及配置哈希；字段拼写错误、无效范围和不相容的快速路径会直接报错。初始化后 `policy-show` 查看现行规则，再用候选配置运行 `policy-preview` 查看逐项差异。预览不写项目文件，也不代替风险审批。

```sh
node src/cli.js policy-preview --project /path/to/project --config /path/to/candidate.json
node src/cli.js init --project /path/to/project --config /path/to/candidate.json
node src/cli.js policy-show --project /path/to/project
```

自定义页面宜按“项目范围、验证、执行环境、预算、分支与发布”分组填写，先显示当前值与候选值，再显示受影响的门禁和明确的宿主机提示。只允许编辑项目规则，不提供关闭内置门禁的开关。保存前由服务端调用 `validateConfig`，保存后重新生成全局项目基线；已审批需求的配置哈希不一致时，现有门禁会拒绝继续，需在新基线上重新评审。当前项目没有在线修改配置的 API，管理员通过受控文件流程管理配置。

## 当前不能由配置解决的边界

Pi 与本地部署仍在宿主机，路径守卫和环境变量白名单不等于进程沙箱。检查沙箱也只覆盖配置的项目检查命令。跨机器团队部署还需要可信身份源、TLS、外部不可变审计与凭证管理；这些不能通过在 JSON 中填写一个“安全”标志获得。
