# pi-reqflow

本地需求工作台。产品确认需求并指定研发负责人，研发授权 Pi 在项目副本中编码。单测和独立审核通过后，产品可以验收，研发可以将差异应用到原项目或回滚。

## 首次启动

使用 macOS 和 Node.js 22.19 或更高版本。执行器依赖系统自带的 `/usr/bin/sandbox-exec`。模型工具使用 `rg` 和 `fd`，使用 Homebrew 的环境可以通过 `brew install ripgrep fd` 安装它们。

在克隆下来的工作台仓库里运行下面的命令。将第二条命令中的路径换成**需要 Pi 开发的已有项目目录**。

```sh
npm ci --ignore-scripts
npm run setup -- "/要接入的项目目录"
npm start
```

首次配置会提示设置管理员密码，输入时隐藏字符。打开 [本地工作台](http://127.0.0.1:4173)，用账号 `admin` 和刚设置的密码登录。以后只需运行 `npm start`。如果 4173 被占用，可以运行 `npm start -- --port 4180`，访问终端显示的地址。

## 配置项目

1. 打开“项目设置”，添加兼容 OpenAI Chat Completions 的供应商，填写 API 地址、API Key、模型名称、上下文和输出上限。按供应商协议选择系统消息角色及输出上限字段，分别为 requirement、development、review 选择模型。
2. 设置任务预算和执行策略。把依赖和构建产物排除在源码快照之外。项目已有的 `node_modules` 可以登记为只读运行依赖。默认从来源根目录识别 `package.json` 的 `test:unit` 或 `test` 脚本，其他布局可在“自定义工程检查”中填写实际命令和工作目录。
3. 打开“项目初始化 / 图谱”，配置独立的初始化预算，填写要梳理的业务范围并开始。业务模块通过独立审核并发布后，即可创建需求。梳理和需求执行分别消耗对应预算。
4. 需要多人协作时，在“用户管理”中添加产品和研发账号。后续项目通过“导入项目”接入，支持单一根目录或独立的前后端目录。

模型凭据加密保存在本地账号库。已有凭据的执行设置可以参考[配置样例](examples/delivery.json)。管理员也可以通过命令行将设置应用到已接入的项目。

```sh
node dist/cli.js configure --project "/已接入的项目目录" --file "/执行设置.json"
```

## 本地资料与运行范围

全局注册表和首次创建的账号库保存在 `~/.reqflow/`。要使用独立状态目录，请在首次配置和后续启动时设置同一个 `REQFLOW_STATE_DIR`。业务项目的 `.reqflow/` 保存项目配置、隔离工作区、审核和交付记录，请将 `.reqflow/` 与 `.reqflow-init/` 加入业务项目的 Git 忽略规则。

工作台仅监听本机回环地址。研发命令和项目单测可以访问网络，沙箱限制写入并保护账号库，其他本机文件仍可能被命令读取。请接入受信任的项目和模型供应商。首次登录和保存配置无需模型调用，点击测试模型连接会发送一次真实请求。

可用 `npm run check` 执行静态检查，用 `npm run build` 编译工作台。项目许可证为 [MIT](LICENSE)。
