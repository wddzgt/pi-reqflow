# 执行上下文与预算控制

## 已落实的工程措施

- 初始化理解按源码与执行策略绑定并复用。供人阅读的完整指南保留；日常模型读取结构化概览、架构、规范和待核实事项。
- 项目原有 AGENTS.md、AGENTS.override.md、CLAUDE.md 单独读取并核对源码哈希。实施携带根目录及所改文件祖先目录的规则原文，不用模型摘要替代规则。
- 跨需求源码证据提供文件、行号和哈希索引；不把此前所有源码正文重新塞进每次请求。专项评审只获取本次相关文件的事实，不读取其他 Agent 的结论。
- 方案草稿和已完成专项检查保存检查点。同一需求、源码、基线、配置、规范及审核反馈未变时，重试仅调用未完成检查；回归基线检查仍完整执行。任何校验不匹配或证据篡改都停止，不把过期结论当作当前审批依据。
- 实施按方案中的真实函数名和责任人引用的行号定位源码，标明完整文件与局部片段。默认允许为同一验收目标补充项目授权路径内的必要文件，实际新增范围进入差异审核；精确方案、快速路径和具名修复仍按批准清单约束。小需求正文12 KB，标准需求24 KB，有界复杂需求32 KB；只读评审正文6 KB，整个请求仍受项目上下文字节限制。
- 具名修复由已接单的方案审批人给出诊断和文件范围。源码、工作区、快照及审批必须仍匹配；提供诊断相关函数与完整冻结契约，允许核实缺失依赖，明确关闭研究的修复才使用仅证据模式。
- 每个文件的独立替换合并成编辑批次，每个替换最多 50 行。历史工具调用完整保留匹配原文与实际 newText，不注入占位参数。只压缩超过512字节的成功结果正文，失败调用及原始日志不修改。全部获批文件完成写入后，关闭工具，只发小的终结提示。
- 模型文字不代表交付成功。控制器检查实际差异、运行真实检查，再由研发选择本地人工验证或发布固定测试环境；发布后等待人工业务验收。同一快照的通过证据可以复用，不增加固定重复审批。
- 产品上下文仅保留当前未解决的人类补充、最新分析和未确认候选。已经形成候选的早期讨论改为事件引用；大段原始需求只给有界预览，缺失细节用 `read_discussion` 读取当前需求的精确原文。原文不删除，摘要和候选不是已批准事实。
- 研发沟通保留完整冻结需求，发送方案导航、意见导航和本版本最近四条有效交流摘录，历史摘录合计最多4000字节。项目规范原文、接口样例、伪代码和历史对话留在磁盘；有具体判断需要时，使用 `read_plan` 按精确方案哈希及章节读取，每次最多1000字符，或 `read_discussion` 按事件哈希读取原文。摘要及引用进入审计，失败日志不作为研发意见，压缩后仍保留冻结需求和版本引用。直接编辑是待核实提案，AI 建议不能绕过业务边界和研发确认。
- 复用 Pi 原生压缩，压缩后重新注入冻结需求、批准方案、权限、当前状态和证据引用。原生摘要调用可能不经过普通请求钩子，压缩前按原生准备信息预留一至两次摘要调用与 token，结果计入同一需求用量；失败或未返回计量时明确停止。
- 归档不默认进入项目上下文。`search_history` 必须给出明确检索理由，仅检索当前项目的已验收归档，最多三条摘要。`read_history` 先匹配本会话搜索结果，再读取一个验收项的有界原文片段，带偏移、总长度和完整证据哈希。历史功能是否存在于当前源码仍需核实。

## 预算口径

需求累计用量覆盖产品分析、方案、专项检查、实施，以及所有失败和重试。`maxModelCalls` 按实际模型响应累计；adaptive 记录目标及超出情况，strict 将剩余调用额度交给执行器。管理员更换模型不重置计数，供应商明确零用量拒绝不占业务响应额度，物理尝试序号仍完整保留。

默认 `admission.budgetMode=adaptive` 按已审核方案的文件数、模块数和预计变更行数给出阶段 token 目标。小需求3万、标准需求6万、有界复杂需求12万，方案分析6万。超过 token 或累计响应目标不会直接判失败；请求前需要更多额度时记录目标扩展、实际累计量和原因。显式选择 `strict` 才执行累计 token/响应硬门禁；每阶段请求次数、累计时间及自动修复仍有限制。方案修订次数硬限制适用于 strict 及委托自动修订，adaptive 允许研发显式发起收敛；失败后责任人显式诊断续行，避免无效循环。

adaptive 实施的阶段请求上限按小/标准/有界复杂需求分别采用 `modelUsage.maxRequests` 的1/2/3倍，并受本次承接允许的阶段调用数约束；默认基数8对应8/16/24次。初始化及只读阶段不扩大。strict 保留原阶段硬上限。实际分配保存在遥测 `requestLimit`，用于容纳分段编辑与检查反馈，不重置任何累计用量。

序列化上下文字节是另一项独立目标。adaptive 只在原请求前缀逐字相同且相同模型已返回输入计量时，核对该输入、新增字节预留和输出仍在配置窗口内，再允许字节目标扩展并记入 `contextExpansions`。没有这一证据或选择strict仍停止。工具参数不压缩成占位符，避免模型把占位符当作源码。

请求前按序列化请求字节数预留输入，strict 不足时停止。当前输入预留为字节数除以二，属于保守估算，**不是供应商 tokenizer 的精确计量**；图片和特殊编码仍有误差。供应商返回的全部输入、输出和缓存 token 为最终计量，失败与重试同样累计。

价格未知时不得把 `costUsd=0` 显示为免费。模型额度耗尽时明确停止，由管理员在模型设置中修改并测试连接；系统不自动切换模型，也不开启付费。

## 失败与审核

越权与未知工具错误明确停止，禁止失败读取后猜测方案。所有阶段的只读结果超限可缩小参数后重新读取；实施中的原文匹配、无实际变化和单次替换行数错误也可在原会话纠正，合计最多两次，原错误、调用 ID 和用量全部保留。结构化业务输出在支持的模型上使用严格 JSON Schema，程序继续核对语义与证据。已有方案和产品分析校验反馈不能删除验收项、隐藏风险、填补未知事实或代答业务问题。工具只能定位当前隔离工作区，方案文件名需与真实源码大小写一致，避免本机与 Linux 行为不同。

责任人引用源码时，每个范围都写完整文件名，例如 `src/service.py:1-40; src/service.py:100-130`。责任人已归档的方案澄清与批准备注均参与源码定位，写权限由当前项目范围或明确收窄的批准清单决定。

执行器在首个请求发送前明确拒绝的调用记为零用量；已发出但没有完整计量依据的调用仍是未知用量，阻止继续消费。不能用零值掩盖网络中断造成的不确定结果。

方案只列实际拟改文件，既有回归文件列入验证要求。责任研发人可用 `approve-plan --scope-file` 缩小写入范围并记录理由；不能扩展原方案、解除阻断项或削弱回归。原方案、选择、审批人与证据哈希都保留。

## 参考与取舍

- [Aider repository map](https://aider.chat/docs/repomap.html)：采用有界的文件与符号定位信息，相关源码按需读取。本项目尚未实现完整符号依赖图。
- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：使用轻量引用、按需取证和阶段相关上下文，避免无差别累积。
- [LangGraph durable execution](https://docs.langchain.com/oss/javascript/langgraph/durable-execution)：参考检查点与可重放任务的设计，保留阶段证据和失败尝试；本项目仍由自己的状态门禁控制部署，不能把不确定的外部副作用当作可直接重试。
