# 需求对齐与研发方案分析

当前已实现产品多轮需求沟通、PNG/JPEG 多模态输入、候选需求修订与定版、全过程审计、成员接单、研发方案分析及按风险触发的一次综合审查。模型职责固定为 requirement、development、review。文档附件提取、正式 OIDC/SSO 和敏感资料自动检查仍待接入；下文涉及这些能力的描述属于后续扩展设计。

## 目标与边界

产品先描述业务问题并上传资料，需求 Agent 给出建议和必要的问题。产品定版后，开发 Agent 只读分析并形成方案、拟改文件、影响依据、验收场景、相关检查和本地启动方式。默认在持久化数据或外部效果需要核实时，增加一次审查 Agent 的综合审查；普通历史行为与接口改动由责任研发及相关验证把关。配置 full 时每份方案执行一次综合审查。未知影响与阻断问题必须解决后才能批准，复杂设计由研发主导。

常规流程由产品负责人确认“做什么”，研发审核人批准“怎么改”并审核验证后的实际代码差异。快速路径限于有明确无影响依据的方案，仍在方案批准及实际变更审核处暂停；存在历史功能、接口或数据影响时退出快速路径，按常规流程由责任人审核。Agent 没有审批权。测试环境仍需人工验收，生产发布另有独立审批门禁。

## 状态与产物

| 状态 | 进入条件 | 主要产物 | 退出门禁 |
| --- | --- | --- | --- |
| 草稿 | 产品创建需求 | 原文、附件与来源哈希 | 提交完整的目标和上下文 |
| 研发反馈 | 只读分析现有系统 | 当前行为、影响范围、建议、必要问题 | 产品逐项答复或明确暂缓 |
| 需求对齐 | 产品与研发迭代问答 | 可验收的需求契约 vN | 产品负责人确认，阻断问题清零 |
| 方案分析 | 契约定版、研发接单 | 简短方案、拟改文件、影响依据、验收与回归场景，必要的专项发现 | 分析与专项证据绑定同一版需求 |
| 方案待审 | 分析完成 | 一页内实施方案，细节按需展开 | 未知影响与阻断项清零，具名研发审核人批准 |
| 实施与交付 | 沿用现有工作流 | 变更、检查、部署、归档 | 具名研发审核人批准实际差异后才可测试部署 |

对齐过程中改变目标、验收条件或范围需重新核对并定版。方案及专项检查绑定契约哈希；方案批准前可重新对齐需求，旧方案失效但保留归档；批准后禁止直接改契约。

## 需求契约

冻结后的最终需求是各研发 Agent 唯一的业务输入，包含业务目标、当前行为、期望行为、验收条件、本次包含与不包含的业务事项。已确认的业务规则和限制整合进这些字段，问答映射 `answers` 保持为空；来源和讨论留在审计链中供回看，不自动进入研发提示词。未知信息必须在产品沟通阶段追问，不能由模型补默认值。

产品原文和研发建议保留为不同来源。问答记录逐项保存提出者、答复者、时间、结论与对应契约版本，避免把 Agent 的推测写成产品决定。确认页面只展示变更后的条款、未解决问题和验收条件。

产品沟通只使用业务语言。AI 可内部读代码，但不能向产品直接给出函数、文件、HTTP 定义、接口字段或数据库设计，也不能要求产品决定这些技术事项。技术影响应译成业务问题，如“取消订单后能否恢复”“原订单是否仍可查看”。定版后，方案分析定位源文件、接口、数据和回归文件，形成 `affectedFiles`；它与业务 `inScope` 分开记录、绑定审计哈希。快速流程检查研发文件范围，仍停在人工方案审批和实际变更审核。

## 按决定依赖澄清

每轮分析保存 `decisions=[{id,text,sourceEventHash}]`，引用本需求产品原文；这是当前业务理解，只有产品定版后才形成冻结需求。`questions` 和 `deferredQuestions` 均包含 id、text、dependsOn 和 recommendation。当前问题只依赖已说明的决定；依赖未决问题的事项留到后续，前置回答后重新计算。产品可自然回复，不必维护依赖表。没有有效来源、依赖不存在或循环、编号重复及仍有后续问题却声称 ready 均报错。

最新产品修订会替换受影响的当前理解，旧决定原文和旧分析继续保留。AI 查证代码事实，不把普通技术调查交给产品。页面按需展开已说明的选择及原话，后续问题不提供本轮作答框；最终候选仍需产品逐版本确认。

## 多模态附件

创建需求和产品补充对话使用同一个图文输入区域。可粘贴、拖入或选择 PNG/JPEG 图片，再写说明，一次发送；补充对话允许只有图片，禁止发送空消息，创建需求仍须填写原始描述。图片预览和移除按钮位于输入区域内，读取中阻止发送，发送失败保留草稿，成功后清空。每条消息最多 4 张、每张最多 1 MiB；进入模型的本轮资料最多 12 张、合计 8 MiB。

系统保留原件、MIME 类型、大小、上传者、时间与 SHA-256，并将图片和同条文字绑定归档。模型直接接收图片像素及消息与图片顺序映射，联合理解图文；不会先用替代文本覆盖原件。分析结果绑定原始输入哈希，历史中可回看对应图片。文档提取和敏感信息自动检查仍属后续能力。

附件属于不可信输入。其中的指令文字只能作为需求资料，不能改变 Agent 的工具权限或工作流。按项目和角色授权访问附件，检查类型、原件哈希、大小与总量。模型未声明图片能力或实际消息未包含完整图片时明确报错，不静默忽略附件。

## 研发方案分析与专项检查

`plan` 由开发 Agent 返回结构化改法、影响依据、验收断言，以及 validation 中的相关检查、跳过原因和本地启动方式。系统执行方案所选的基线检查并保存结果，生成供研发阅读的文档，模型不重复输出 Markdown。审查 Agent 按 risk-based 或 full 策略执行一次综合审查。未知影响先补证据，不能因调用审查就视为已解决；审查意见不能替代责任研发的批准。

审查 Agent 接收冻结需求与方案分析，综合检查前后端、回归、数据和恢复风险，输出严重程度、具体问题、源码依据与建议。检查真实遗漏和冲突，不重复生成方案，不因自然语言或接口 JSON 的措辞不同制造分歧。结果必须引用同一契约哈希与方案分析哈希。

1. 每条验收条件都有待执行场景和既有功能回归检查；文字场景不代表测试通过。
2. 历史行为、接口、数据分别声明无影响、涉及变更或未知，并给出依据；未知影响阻止批准。
3. 专项发现分为阻断与建议；建议不因措辞不同造成阻断。
4. 阻断项显示在同一份方案中，由研发补充意见重分析；涉及业务决定时，回到产品重新定版。

不会反复自动让 Agent 互相说服来制造共识；失败与重新分析按尝试归档并计费。专项失败保留原因、角色、模型用量和日志，流程退回待分析。管理员统计实际模型调用，方案汇总事件不重复计费。

页面只展示“研发方案”一关，默认显示短摘要；影响证据与专项建议折叠。审批与实施均验证方案分析及专项文件哈希。实施超出获批文件清单直接失败并保留实际差异，快速路径会尝试回退。原有 `run-review` / `finalize-review` 仍可显式用于集成实验，默认链路不调用、不依赖其接口文字一致性结果。

## 权限隔离

权限在服务端按项目、需求和动作检查。身份来自可信登录会话，审计中的操作者由服务端写入，前端不能提交任意 actor 名称。产品提交后指定已注册的研发成员；成员接受分配后才可执行该角色动作。管理员可读全项目需求、审计报告及历史提交记录，但不能借管理员身份跳过审批状态门禁。项目身份的增删由拥有项目文件权限的本机管理员通过 CLI 执行。

| 主体 | 允许的关键动作 | 禁止的关键动作 |
| --- | --- | --- |
| 项目管理员 | 分页查看全项目需求、事件历史和身份变更审计 | 确认产品契约、审批方案或发布、实施代码 |
| 产品负责人 | 创建和补充需求、上传资料、回答问题、确认契约 | 修改代码、批准实施或发布 |
| 已接单研发审核人 | 反馈、确认技术评审、批准或退回方案、核对实际差异并承担变更风险 | 冒充产品确认业务规则、操作未参与的需求 |
| 前端／后端／测试 Agent | 在授权资料范围内只读评审并提出差异 | 自行确认契约、批准方案、改动代码 |
| 实施 Agent | 方案批准后在隔离工作区按允许路径修改 | 改审批记录、直接发布生产 |
| 测试验收人 | 查看验证证据、记录测试结论 | 替代研发方案审批 |
| 发布审批人 | 核对已验证候选版本并批准发布 | 修改需求契约或跳过验证 |

当前 `admin` 不能兼任交付角色，产品与研发审核、生产发布审批人与实施者分离；Agent 永远不拥有人工审批权。其他成员只看到自己创建或被分配的需求，且只有接单后才可执行对应动作。服务端按对象级范围检查，不能只靠页面隐藏按钮。CLI 和 API 走同一核心动作入口，避免绕过页面审批。

## 页面交互

产品视图采用“提交原文和图片 → AI 研发分析与追问 → 产品自然回复或修改候选需求 → AI 核对 → 产品定版 → 指定研发成员”的短路径。建议和较早沟通可展开查看，原始输入始终保留。定版展示最终目标、行为、范围和验收口径；提交绑定当前分析哈希，旧页面不能确认已变化的版本。研发成员接单后进入统一方案分析。

研发视图以“分析并生成方案”为单一入口，显示拟改范围、验证方式、影响与真正阻断问题。进度为需求对齐、研发方案、代码实施、验证测试、发布观察、交付归档。进度条区分产品定版与研发批准，专项 Agent 不单列一关。

## 实施顺序

当前实现保留每轮产品原文、图片原件、候选修改、AI 分析、追问、失败原因、模型用量及定版关联，以及每版方案和专项证据。图片撤回仅取消后续模型引用，原件及撤回事件不会删除。方案批准前支持重新对齐业务需求，批准后禁止直接改需求。后续补齐文档提取和可替换的团队身份源，沿用归档及工作区回退链路。
