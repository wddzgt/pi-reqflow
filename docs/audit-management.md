# 审计与管理报表

## 展示分层

| 入口 | 查看内容 | 使用人 |
| --- | --- | --- |
| 项目审计与交付总览 | 当前积压、待人工处理、异常、未落实负责人、归档、回退；阶段分布和负责人工作量 | 当前项目管理员 |
| 需求生命周期 | 从创建到归档的关键事件、当时的负责人、决定人、发起人、需求和方案版本 | 需求创建人、当前指定且未拒绝的研发成员、管理员 |
| 原始事件与证据索引 | 完整事件、历史状态快照、批准证据、变更清单、日志位置、哈希链 | 管理员 |
| 执行诊断与模型用量 | 失败原因、模型阶段、关联 trace、计量覆盖率和执行日志索引 | 管理员网页；授权成员也可通过核心观测接口查询自己的需求 |
| 身份变更历史 | 账号创建、撤销、权限变更、密码操作及可信发起人，不记录密码或令牌 | 管理员 |

产品需求原文、图片及每轮沟通仍在“需求对齐”中完整保留。生命周期不重复展示沟通全文，研发下一步仍只接收冻结的最终需求。

## 管理指标口径

- **进行中**：排除生产观察归档、测试归档和工作区回退的需求。
- **待人工处理**：当前流程处于产品确认、指定研发、接单、研发反馈、方案审批、变更审核、测试验收、发布审批或发布观察等人工节点。异常单独统计，两者可以重叠。
- **需处理异常**：当前尚未解决的需求分析、方案专项检查、方案阻断项或未知影响、实施、验证、部署、候选验证、发布、回退或预算阻断。统计需求数，不按失败日志条数放大。
- **待落实负责人**：当前活动阶段没有对应负责人。需求沟通及定版后尚未指定研发的分配事项归产品，研发反馈和研发后续阶段归指定研发。缺失身份明确展示，不推断审批人。
- **完成归档**：生产观察归档与测试归档合计；**已回退**独立计数，回退不作为成功交付。
- **状态停留时间**：从最近一次状态变化开始，重复部署查询和同状态事件不会刷新。按时长列出最久的 5 条活动需求，没有配置 SLA 就不称为“超时”。
- **归档周期中位数**：创建至进入归档状态的时间，只取归档样本，同时显示样本量。零样本明确显示未知；后续诊断事件不会延长周期。
- **模型成本**：只包含需求的模型调用，项目初始化费用不纳入。展示已知成本和已计量次数；有缺失计量时总成本为 `null`，不能把未知成本显示成零。

全项目统计基于索引中的所有需求验证后计算，不随需求列表分页或筛选改变。列表可按需求编号/标题、产品或指定研发 ID、状态、待处理异常筛选。报表按项目授权，不跨项目汇总其他项目的数据。

## 生命周期与执行证据

关键业务事件保留定版、成员分配/接单/拒绝、方案阻断与修订、批准、修改、验证、验收、部署结果核实、回退和归档。专项具体结果随方案证据保存，失败单独展示。

管理时间线省略模型分析启动、中间草案、文件准备、成功专项调用、缓存跳过和重复部署查询；这些原始证据保留供诊断。方案形成时统一展示结果，不把每次模型调用计为一关。工作区准备和候选版本准备分别作为“开始代码实施”“开始候选版本验证”展示。预算耗尽使用 `pi_budget_exhausted` 展示阻断，不与普通跳过混淆。

独立角色的失败按角色消除；某角色重试成功不会消除其他角色的问题。重新定版清除被废弃契约的评审/设计问题，但历史事件仍可回看。部署结果未知必须由成功部署证据或人工核实消除。报表只读，不改变任何审批、权限、隔离和回退门禁。

每个时间线节点包含原始事件序号和哈希，管理员可直接定位该节点原始证据。分页默认最新事件在前；没有最近 100 条的截断。原始审计按原始顺序分页，前后节点通过 `previous` 和 `hash` 关联。

## 身份、记录与保存

通过核心动作入口执行时，`initiatedBy` 和 `action` 由认证上下文写入，客户端无法指定操作者。人工决定保留实际 `actor`；自动阶段记录流程执行器/模型角色，并绑定发起人。管理员网页账号操作同样绑定登录管理员。CLI 本地账号管理记录 `host:<操作系统用户名>`，需求动作再绑定令牌认证身份。

直接使用低层函数的集成方必须在自己的可信身份边界建立同样的审计上下文，建议统一调用 `executeRequirementAction`。历史事件缺失的身份保持未知，不回填成某个审批人。

查询、刷新、统计计算不创建需求事件。沟通正文只存原始沟通记录；管理时间线和报表从已验证的事件生成，不再写一份冗余管理日志。批准证据、源文件快照、外部结果未知、失败和安全身份变更属于必要记录，不能为减少噪声删除。

## 核心和适配接口

```js
const report = await getAuditReport(projectPath, adminPrincipal, 0, 50,
  { owner: "developer", attention: "true" });
// summary、usage 始终为全项目口径；total 为筛选后数量；requirements 为当前页。
const lifecycle = await getRequirementLifecycle(projectPath, memberPrincipal, "REQ-101", 0, 50);
```

- `GET /api/admin/report?owner=developer&attention=true&offset=0&limit=50`
- `GET /api/tasks/:id/lifecycle?offset=0&limit=50`
- `GET /api/admin/tasks/:id/history?offset=0&limit=50`
- `GET /api/admin/tasks/:id/observability?offset=0&limit=25`
- `GET /api/admin/auth-history?offset=0&limit=50`
- CLI `lifecycle --project <项目> --id <需求>`；`audit-report` 支持 `--owner`、`--state`、`--query`、`--attention true|false`。

## 当前边界

报表逐需求验证本地事件链，成本随项目规模和图片/模型证据体积增加；目前没有数据库投影、历史趋势仓库和外部不可篡改存储。全项目读取不保证跨需求的数据库事务快照。

哈希链可以检测常规文件改动，不等同于外部签名或不可篡改存储；管理页面展示审计文件/日志索引，完整日志文件仍由受控本地存储或使用方日志系统读取。需要大规模团队部署时，可将同一核心事件投影到查询库，并把审计头锚定到外部存储，保持原始链和核心权限为依据。
